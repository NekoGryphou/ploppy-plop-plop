# Security

## Reporting a vulnerability

Please use GitHub's private security-advisory reporting for this repository. Do
not open a public issue containing credentials, pairing codes, or exploit steps.

## Protocol security model

Decky My Rig is designed for a trusted home LAN, but it does not trust arbitrary
LAN clients. Pairing uses SPAKE2 with a six-digit code generated by the Windows
host from operating-system-backed cryptographic randomness. Codes expire after
five minutes, allow at most five failed key confirmations per source, are single-use, and
regeneration invalidates the previous code. Started exchanges are bounded per
source and globally and remain independently addressable by random session
identifiers, so one start cannot overwrite another. The code is
available only over the Windows-local
named pipe. That pipe grants access only to LocalSystem and elevated local
Administrators, and the WinUI control application requests elevation before
connecting. The LAN API has no code-retrieval route.

Successful pairing returns a random 256-bit credential encrypted with
ChaCha20-Poly1305 under a key derived from the SPAKE2 shared secret with
HKDF-SHA256. Host identity and protocol metadata are authenticated as associated
data. Subsequent requests use HMAC-SHA256 over a domain-separated canonical
request containing the timestamp, nonce, method, path, and body digest. The host
rejects stale timestamps and reused nonces; accepted shutdown nonces persist
across service restarts. Every response produced after successful request
authentication, including structured HTTP errors, uses a separate HMAC domain
bound to the request nonce, path, HTTP status, and exact response body. Clients
reject unsigned or tampered success and error responses before interpreting them.

The host persists a completed pairing before consuming its pending exchange and
briefly caches the encrypted result. If the final response is lost, an identical
retry returns the same committed credential instead of rotating it again.

The protocol uses HTTP, not TLS. Pairing and credentials are protected and
authenticated, and authenticated operations have request/response integrity,
but IP addresses, timing, HTTP paths, and status response contents are not
confidential. A LAN attacker can still deny service by dropping traffic.

Windows credentials and pairing state are protected with machine-scope DPAPI in
an ACL-restricted ProgramData directory. Decky-side credentials are stored in a
mode `0600` file inside Decky's plugin settings directory because Decky does not
provide a platform secret-store API; compromise of the Deck/root account can
therefore recover them.

## Dependency policy

Run `./scripts/security/audit.sh` to query RustSec, npm, and PyPA advisory data.
The Windows build treats NuGet vulnerability warnings as errors. Vendored Python
wheels are version- and SHA-256-pinned, and Dependabot covers Cargo, npm, pip,
NuGet, Docker, and GitHub Actions manifests.

Tagged releases require an Authenticode certificate supplied through protected
GitHub release secrets. The workflow signs and verifies the host, control app,
and installer; publishes CycloneDX SBOMs and SHA-256 sums; and requests GitHub
artifact provenance attestations. The control app independently verifies the
installer checksum, Windows trust result, and the embedded release-certificate
thumbprint before elevation. Configure `WINDOWS_CERTIFICATE_BASE64` and
`WINDOWS_CERTIFICATE_PASSWORD` only in the protected release environment; a
tagged release intentionally fails when the certificate is absent.
